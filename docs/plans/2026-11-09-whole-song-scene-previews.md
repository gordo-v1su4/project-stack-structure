## Behavior and boundaries

Story hosts scene preparation and review inside Setup → Story → Draft → Finish. Initial suggestions come from the actual confirmed treatment and timed song map. They are proposed direction, never approved media. Independent scene windows may divide a long music section; their ordered coverage must span the actual full song without gaps or overlap.

Each scene keeps three distinct moments, a named reference authority packet, precise song window and separate review. Main scene-direction edits rebase seeded moment prose and reach the actual submitted image prompt. Each moment uses only identities named in that prose and the selected environment authority. The still target is a bounded subwindow of an existing saved placement; preparing a still never changes the edit or fills video coverage.

Reuse the dedicated owned MiniMax still API, Trigger task and SwarmUI-managed provider. There is no paid/legacy-board fallback or alternate raw ComfyUI provider. Its pinned model/profile, worker packaging, actual runtime readiness and creative suitability remain real activation gates; a source button does not prove those are satisfied.

The entire per-moment intent is saved with CAS before its single POST. Browser keys are scoped per project/scene/moment, with durable project records as reload/device authority. Uncertain submission uses GET-only recovery, bounded attempts and immutable job identity. Changes during save, project switches and late acknowledgements cannot submit or install a stale scene result.

Human scene-direction approval requires three current ready proofs. It binds story/canon, song map, scene/window/prose, ordered selected references, canonical job/descriptor and master/native/artifact identities. Runtime URLs, ordinary saves and review state do not self-invalidate the editorial context. A changed scene invalidates its own moment bindings; shared story/reference changes invalidate the applicable context. Historical provider jobs remain immutable. Stale images are labeled and cannot be presented as current proof.

New video dispatch and unsubmitted workers enforce full-song scene review once the project has opted into a scene plan. The server rereads owned ready jobs and checks exact frozen requests, descriptors, actual pinned reference versions and stored results. Copying client proof fields or recomputing a review hash is insufficient. Still generation has its own pre-submit context check and does not require scene approval, avoiding a preview/approval deadlock. Submitted historical recovery remains unchanged.

Scene direction, generated-take review, exact-draft consent and export acceptance remain distinct. No scene approval selects a take or authorizes a final export.
