# Current-reference identity migration

Approved implementation scope: preserve immutable generation evidence while explicitly migrating the film's current reference authority. The sharper Diego PNG (`e71f4d4325a61641d98de57604ff09e425aeefd07f994606f189c06f88c47c4a`) is already user-approved; see the current completion map. Historical jobs correctly bind the earlier PNG and must never be rewritten to claim otherwise.

## Contract

- Additive source confirmation continues to reject any replaced raw image.
- A distinct immutable migration receipt binds owner/project, fresh CAS revision and baseline hash, unchanged story/full placements/settings/media versions, exact old reference/job/target/proof lineage, approved replacement versions, and freshly conditional-read current reference pins. Stable arrangement scope remains unchanged; original targets, policies, assets and assessments remain exact.
- The migration is not active until an explicit project CAS saves its receipt pointer. Enrollment/policies/CPU results never save or select a project. Lost project-save ACK is reconciled by GET; no replay.
- A separate current-reference assessment purpose/schema binds original job/media/target/parent proof and exact native selected range independently from current reference hashes/gallery/issued evaluation policy. Generation hashes remain historical. Existing generation and v1 range verifier contracts stay unchanged.
- Reuse the existing CPU model, frame traversal, tracking and numerical filters. Do not weaken family, geometry, dominance, margin, threshold or every-frame coverage gates. Current-reference evidence remains provisional and unverifiable, never a likeness certificate.
- Require both original eligibility and current-reference eligibility for affected draft selection, approval, approved preview/coverage, first-frame source reuse and export. Preserve the bank and selected IDs while evidence is pending/failed. Unaffected identity/environment/editorial entries retain their proper existing gates.
- Every approval fingerprint includes migration and current assessment digests. Migration resets full-cut consent and export state. A changed reference version, exact range, target, media, parent proof or policy invalidates the corresponding current evidence. Unrelated supplemental library appends can retain an exactly unchanged evaluation context but require fresh cut consent.
- New generation uses genuine current E71 references and a normal newly issued generation policy. Neither an old job nor its policy is retargeted. Normal independent new projects remain supported.

## Implemented checkpoint

The migration endpoint prepares an immutable receipt and revision-bound candidate; project adoption calls `validateReferenceMigrationAdoption` inside the existing CAS update. The receipt binds both full baseline and exact candidate digests. Already-active context cannot be dropped, switched or silently rebound. Assessment history and active pointers are separate, and every pointer save retrieves the canonical assessment, original job and evaluation policy. Visible previously approved overlays are requeued into the new review selection without changing the bank or original pending selection order.

`/api/generate/h3/current-identity` freezes a durable intent and dispatches the existing `local-ai-generation` task with mode `current-reference-assessment`. There is no new task slug or GPU call. GET accepts the request ID or original UUID for lost-acknowledgement recovery. Only a valid exact lookup under a freshly verified owned existing project can return HTTP 404 `CURRENT_IDENTITY_REQUEST_NOT_FOUND`; missing projects and invalid lookups never assert request absence. Definitive preclaim rejection returns `CHECK_NOT_SUBMITTED`; any possible durable claim/submission returns `SUBMISSION_UNKNOWN` with HTTP 503. Results never save or select the project. The current-purpose CPU policy preserves each original screen: the two fixed legacy policies retain single-face `.94` detection and all original numerical rules; issued foreground policies retain their actual family and dominance rules.

The purpose-specific report carries historical origin hashes and separate evaluation reference hashes. Strict shared frame/score normalization rejects mixed generation fields, invalid hashes, nonfinite/nonnumeric scores, empty tracks and malformed dates; private diagnostics and embedding-shaped extras are discarded before storage. Original approval digests remain unchanged. Fresh current-reference consent uses `approvedCurrentReferenceEvidenceSha256`, plus a full-cut context digest. Final export canonically rechecks actual current overlays and includes both original and current evidence receipts; superseded approved history is retained without blocking the cut.

A migration-authorized historical resolver can read the backed-up original Diego bytes using the backup's own conditional ETag and full old SHA. It never changes the original job's reference key/ETag, never claims the backup locator was the generation input, and never falls back after a failed read. This permits explicit later historical range checks while the current-reference screen remains separately required.
